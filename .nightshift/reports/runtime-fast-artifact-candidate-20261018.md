# Private fast-artifact candidate, 2026-10-18

This branch introduces two source-bound private artifact adapters, `go-broker-artifact.ts` and `native-observer-artifact.ts`. Ordinary `node runtime/src/cli.ts chat` still selects the existing PowerShell path. The adapters do not build, install or enable binaries and are not a production artifact authority. The 30-second healthy new-save and acknowledged-restart goal remains open; no real-provider timing was accepted.

The Go broker adapter admits a single-link ordinary binary under the installation worktree with SHA-256 `aa52d71f8a2243bdcb83bc394a12fe8193e413eb70b3543130f69df5a99c5d13`, pins its five source files, launches with the existing version-2 owned-process control protocol and repo-local helper environment, and rechecks source and binary identity and bytes at close. It accepts either the complete LF source-hash set from the restricted-build proof or the complete CRLF source-hash set measured in this worktree; mixed sets refuse. (Later note, 2026-10-19: one LF digest in that launcher had been truncated, so only the CRLF set could ever match; the launcher had no callers and was removed. The release path verifies LF-normalized source digests from `compiled-images.json` instead.) A no-VCS Go 1.26.0 build from the CRLF checkout produced the same 3,492,864-byte broker hash as the earlier LF build. The first artifact test refused before launch because the new checkout's raw source hashes differed; a later private `ProcessSupervisor` test in `.tmp/go-artifact-fixture-20261018-b/run/tap.log` passed with process identity, streams and stop proof.

The native job observer adapter pins the observer binary, source and exact manifest, requires fixed Go 1.26.0 and no-build-ID metadata labels in that manifest, and returns the artifact selection consumed by the existing native job query. Those labels do not prove the compiler invocation. The earlier observer binary used a build recipe whose result varied with the source form and module-mode setting. Explicit no-build-ID builds from the LF and CRLF source each produced 3,094,016 bytes with SHA-256 `bb3818599c2b5c5c4da98af42daea4300bfdb3103c0d420009021bd8af313fec`; the source hashes are `41506467461594bb00aab61047371d546e9c1047a0d47c2f3db15e16c2940d26` and `444e29895441e4a3ddd1029d1e0877a92270c49aefdd2b4089996cb8fbb992aa`. The combined `ProcessSupervisor` fixture in `.tmp/native-observer-fixture-20261018/run/tap.log` passed all-role absence, command output, owned-provider liveness, stream forwarding and verified stop. TypeScript type checking with the pinned installed compiler passed. These are separate private observations, not a whole-start saving calculation.

The adapters use the current Node read-handle pin and before/after verification. They do not prove the exact bytes mapped at Windows process creation, a trusted dynamic source-to-binary installation, a complete write footprint for all descendants, real SDK readiness or repeated healthy attachment within 30 seconds. The approved startup design requires the remaining private negative paths, direct source and pre-guard write proof, independent final code and documentation reviews, then user-coordinated live measurements. The failed early SDK probe documented in `runtime-go-first-use-spike-20261018.md` is not acceptance evidence and will not be repeated before those gates.
