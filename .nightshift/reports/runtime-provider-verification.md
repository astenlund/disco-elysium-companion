# Runtime provider verification

Observed on 2026-10-08 with the installed Claude Agent SDK 0.3.289 and its Claude Code 2.1.289 executable. These checks used synthetic messages and private repository fixtures through the production `ClaudeProvider`. They establish the boundaries below, not full coordinator acceptance or live cutover. No probe consumed the real companion root or accessed game saves.

| Boundary | Observed evidence | Limit |
|---|---|---|
| Default-profile request and source readout | A real request completed; native `apiKeySource` was `none`. | This does not identify a unique non-API-key credential kind. |
| Session resume | After closing and restarting the provider, the same session ID recalled a synthetic nonce from the earlier request. | This checks provider persistence; the complete coordinator restart test is separate. |
| Per-question override | Native initialization reported `claude-opus-5-5` for the overridden turn and `claude-sonnet-5-5` for the next ordinary turn. Control calls applied high effort, then restored medium effort. | Native model observations and accepted effort-control calls are different evidence. Restart immediately after an overridden turn remains a separate live claim. |
| Tool inventory and project hooks | Every recorded turn initialization listed exactly the fixed eight tools and no MCP server. The private project hook marker was absent. | User hooks, auto-memory content, and built-in plugin hooks/context were not audited. Advertised skill names remained `design`, `doctor`, and `plugin-authoring`; metadata alone does not establish their origin or reachability. |
| Streaming | Native text-delta events reached the production text callback before completion. | Synthetic response only. |
| Question round trip | One `AskUserQuestion` reached the production permission and question callbacks. The native tool result and completed assistant text both carried the exact host-only answer nonce. | The answer came from a deterministic fixture callback, not an interactive client dialog. |
| Between-tool context | The same synthetic question session's native transcript recorded a post-tool prompt snapshot whose system-prompt array exactly matched the pre-tool snapshot, with the fixed eight tools and a token reminder. | This observes one between-tool attachment pass. The reminder was classified as intrinsic from its attachment type, not independent content attribution. Additional snapshot members remain unclassified, as detailed below. This does not establish complete settings, skill or built-in plugin isolation; the SDK stream alone does not expose every attachment. |
| Interruption | Interrupt was accepted after the first text fragment; native `aborted_streaming` mapped to `interrupted`. | This does not cover every interruption or child-failure timing. |
| Verbatim input | A leading `/help` was answered as text. The same request retained literal `@state/current.json`, reported no attached file, exposed no hidden sentinel, and caused no file-tool hook. The sentinel stayed byte-identical. | This establishes the tested two-block request shape. |
| Project instruction marker | The first answer quoted the marker assembled from the private `AGENTS.md`. | Marker availability is verified; exclusive provenance versus native instruction loading is not. |
| Provider-window refusal | A synthetic 2,000,093-byte player message produced a native `success` result with `is_error: true` and `terminal_reason: prompt_too_long`; the provider mapped it to `contextExhausted`. Exactly one send and one send-admission callback occurred. | Probe-only session settings disabled auto-compaction. A larger 12,000,077-byte attempt instead returned `blocking_limit` and mapped to `providerError`; it did not establish this boundary. |
| Compaction signal | With a probe-only startup overlay reporting a 100,000-token window and 67,000-token threshold, three completed synthetic turns produced one native `compact_boundary` and one provider compaction signal. | The normal provider configuration was unchanged. This does not establish the coordinator's durable `needsState` write or the provider's auxiliary write footprint. |

The first question assertion demanded one exact presentation of the answer and failed despite successful delivery. Its original result was preserved. The corrected assertion was evaluated against that saved exchange, with negative controls for a wrong nonce, missing assistant echo, missing callback and missing native result. No live turn was resubmitted. The first compaction attempt also remains recorded: three turns completed without a boundary after a post-initialization settings change; the successful attempt supplied and verified the startup overlay.

The reproducible provider/interface executables are [probe-provider.ts](../../runtime/test/live/probe-provider.ts) and [probe-interfaces.ts](../../runtime/test/live/probe-interfaces.ts). Native file-tool footprints remain unverified and the runtime keeps those operations refused. Whole-profile auxiliary writes, user-setting isolation, built-in plugin effects, the runtime-mode versus bridge instruction boundary, and running-game cutover remain provisional. The governing [runtime design](../features/companion-execution-runtime.md#verification) retains those distinct verification obligations.
