# Private image-pin transfer spike, 2026-10-18

The private compiled broker and native observer currently hash Node read handles before launching by pathname, which leaves an image replacement window. The earlier [dual-image guard probe](runtime-dual-image-guard-probe-20261018.md) kept a separate PowerShell process alive while both binaries ran. This spike tested a different mechanism: duplicate its read-share file and ancestor-directory handles into the Node process, then let the helper exit before launching either binary. [Windows DuplicateHandle](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-duplicatehandle) documents that the duplicate belongs to the target process and refers to the same object; [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) documents the sharing restrictions.

The successful private run under `.tmp/go-production-20261018/.tmp/transfer-image-pins-20261018/run-c/` first established a same-process no-transfer control: both copied executables could be opened for writing and the test ancestor `run-c` could be renamed and restored. Its PowerShell helper then duplicated nine directory handles and two executable file handles into that same Node process and exited zero. After helper exit, Node write-open attempts failed with `EBUSY` for each binary and ancestor rename failed with `EPERM`; both executables still launched, exiting 125 and 1 on empty input. After Node exited, its outer controller could again open both files for writing and rename and restore the ancestor, with both binary hashes unchanged. The earlier `run-b` had the same broad result but did not record error codes or a no-transfer control; `run-a` failed on a PowerShell parser error and supplies no mechanism evidence.

The helper was then changed to roll back target-process handles on a caught partial transfer failure using `DUPLICATE_CLOSE_SOURCE`. In `run-d/child-result.json`, an injected failure after the third duplicate exited 1; while Node remained alive, both write opens and ancestor rename succeeded before a normal transfer. That normal transfer subsequently passed with 11 duplicates, `EBUSY` and `EPERM` refusals, both executable launches, and post-Node release. Its direct helper wall time was 712.173 milliseconds after the injected control. This tests one caught failure, not an abrupt helper crash or rollback failure. If a helper dies with unknown partial duplicates, the target Node process must not select compiled execution and must exit or retain an explicit poisoned state until it exits.

A separate `run-e` used the existing `ProcessSupervisor` PowerShell broker and its `metadata` role to run the same transfer helper. The child report records 1,612.224 milliseconds for a fresh supervisor setup and 2,987.139 milliseconds for the normal supervised helper call, with a caught three-duplicate rollback control before it. Both role checks were positive, the child and helper exited zero for the normal call, the pins remained effective after helper stop, and the outer controller saw writes and rename permitted after Node exit. These isolated numbers are not additive to a product startup: the product already opens a bootstrap supervisor, while this fixture created a fresh one. Running transfer inside the existing combined bootstrap helper is an unmeasured design idea.

The copied binaries retained broker SHA-256 `aa52d71f8a2243bdcb83bc394a12fe8193e413eb70b3543130f69df5a99c5d13` and observer SHA-256 `bb3818599c2b5c5c4da98af42daea4300bfdb3103c0d420009021bd8af313fec`. The test does not prove functional broker or observer output beyond process creation and exit, every ancestor's independent sharing effect, source-handle versus pathname identity under concurrent replacement, privileged-actor resistance, or any app-controlled write footprint. The helper identifies its target by PID only, not PID plus creation identity, and its full failure cleanup is unproved. No real provider, real-root consumer command, or original SaveGames mutation occurred. Ordinary chat still selects PowerShell and the 30-second goal remains open.
