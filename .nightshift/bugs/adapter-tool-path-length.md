# Adapter tool path length

Tracked from Nightshift run a69edaac-e54c-47ec-ba9c-3e2c5bb3418d (2026-11-13), which added the companion-root length admission ([Deep helper working directories](runtime-helper-cwd-length.md)).

## Recorded evidence

The runtime's installation bound (`installationRootBound` in `runtime/src/launch-directory.ts`, 223 characters for `disco_elysium`) covers the launches the runtime makes itself and the working directory of the core's adapter commands (`adapters/<adapter>`), the latter assuming the 258-character working-directory limit that was measured for Node spawn and the Go broker, not for the core's .NET launch. It does not cover adapter tools that the PowerShell core starts from inside the core-resolved adapter release folder: the Disco Elysium dump tool is `{artifactRoot}/adapters/disco_elysium/dump-tool/dedump.exe`, where `artifactRoot` is `adapters/disco_elysium/releases/<version>/schema-<n>`, about 87 characters below the companion root. The run measured executable-path limits only for Node's `child_process.spawn` (259 characters started, 260 failed) and the Go broker (270 characters started), on one host with long paths enabled. The core's .NET process launch was not measured, so it is unknown whether a root of roughly 173 to 223 characters actually fails at the dump stage; if it does, the user would see the core's generic `command-start-failed` rather than a length message.

## Follow-up

First measure the executable-path and working-directory limits of the core's adapter command launch at the boundary; the working-directory measurement also confirms or corrects the adapter term of `installationRootBound`, which would need adjusting if the core's limit is lower. Only if a limit applies, add a fail-closed length check with its own message where the adapter configuration is resolved and `artifactRoot` is known, so the bridge and runtime paths both refuse a too-long root before the dump stage.

## Resolution

Measurement: `core/tests/Measure-AdapterLaunchLimits.ps1` starts processes through the core's own `Invoke-AdapterCommand` at every length from 250 to 300 characters. On the development host (Windows NT 10.0.26300, pwsh 7.6.10, .NET 10.0.15, long paths enabled) on 2026-11-15, executables started at up to 259 characters and failed at 260 ("The system cannot find the file specified"), and working directories started at up to 258 characters and failed at 259 ("The directory name is invalid"), each boundary clean across the range. A `pwsh -File` script path started at every length up to 300. The working-directory limit matches the 258 characters `installationRootBound` assumes for `adapters/<adapter>`, so that bound is unchanged. The executable limit applies within the reachable range: the Disco Elysium dump tool at 87 characters below the root fails to start for roots of 173 to 223 characters, which the runtime's bound admits.

Fix: under the Acquisition profile, `Get-AdapterConfig` in `core/private/AdapterConfig.ps1` refuses with the new `config` reason `companion-root-too-long` when the adapter directory is longer than 258 characters or a direct-execution entrypoint's resolved path is longer than 259. The executable check runs before the entrypoint's existence check, and both checks run before save enumeration. Script entrypoints run through `pwsh` are bounded only by the working directory. `Get-AdapterResolutionReason` maps the reason and the turn-context `config` registry admits it, so the turn-context bridge, the one-shot `Update-CompanionState.ps1` and the runtime's `Publish-StateEvent.ps1` all report it. `AGENTS.md` and state-extraction sections 7.5, 8 and 10 give the host the remedy: move the companion folder to a shorter path. The state profile, which launches nothing, applies neither limit.

Verification: `Test-AdapterConfig.ps1 -Only LaunchLength` admits a 259-character dump tool path and refuses one of 260, admits a 258-character adapter directory with a script entrypoint past the executable bound and refuses one of 259, and still resolves the state profile at the refused root. The same check failed before the fix, with the 260-character path admitted, and passed after it. `Test-Acquisition.ps1 -Only ResolutionReasons` runs the one-shot, the bridge and Publish against a root one character too long for its dump tool and asserts that each reports `companion-root-too-long`. All measurements come from one host.
