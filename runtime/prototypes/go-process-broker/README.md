# Go process broker

These sources are the release inputs of `runtime/native/go-broker.exe`. `runtime/native/compiled-images.json` binds the packaged binary to exactly `go.mod`, `control.go`, `child_windows.go`, `job_windows.go` and `cmd/go-broker/main.go`, built with `go1.26.0` for `windows/amd64` with `-buildvcs=false -trimpath -ldflags=-buildid=`. Despite the folder name, they are not a sketch: the selected compiled-image chat path launches this binary for every supervised child when its image pins are ready. The compiled selector remains off for players until its acceptance gates pass; see [integrated startup execution](../../../.nightshift/features/runtime-startup-execution-30.md).

`control.go` parses the version-2 control frame with its 1,048,576-byte frame budget, 65,536-token and 524,288-decoded-text-byte config budgets, strict UTF-8, exact top-level fields, duplicate JSON keys, JSON value kinds, required scalar values, protocol version, parent PID, argument array and child environment. `job_windows.go` claims a kill-on-close job that contains the broker itself, and the broker keeps that job handle until it exits, because closing the last handle earlier would end the broker with exit code 0 before it reported the child's code. `child_windows.go` launches the child through `syscall.StartProcess`, retaining the child and parent process handles for creation identity, job membership and wait. Like the PowerShell broker's `CreateNoWindow`, it gives the child its own hidden console, so a console control event inside the child's tree cannot reach the broker and end the whole job. A command name without an extension gets only `.exe`, never another `PATHEXT` extension such as `.cmd`, and a bare name is searched in the system directories before `PATH`; unlike `CreateProcess`, neither the application directory nor the current directory is searched. Any match that is not a directory qualifies, so app execution aliases launch as they do through `CreateProcess`. The lower-level start path sends a non-nil environment slice to `CreateProcess` without the `SYSTEMROOT` that `exec.Cmd` would add. `control_test.go` covers the control grammar, budgets and environment collisions; `child_windows_test.go` covers the explicit environment, stdin handoff after the control frame, the owned header, `.exe`-only name resolution, refusal of a directory match, acceptance of an app execution alias when the user profile has one, and the hidden console flags; `job_windows_test.go` covers job-name admission, and `exit_windows_test.go` runs the test binary as a broker that claims a real kill-on-close job and launches a child exiting with 0, 1 and 7, requiring the broker's own exit code to match each. No unit test checks that closing the job ends a surviving child. `runtime/test/release-go-broker.test.ts` repeats the exit-code check against the packaged `go-broker.exe`.

The binding above is a recorded claim, not a provenance proof. Among the acceptance gates the [startup design](../../../.nightshift/features/runtime-startup-execution-30.md) lists for enabling the selector, these concern this broker and remain open. First, source-to-binary provenance and trust in the release hashes are unverified. Second, environment names are compared by `strings.ToUpper`, and parity with the PowerShell broker's ordinal-ignore-case comparison is tested only for ASCII names. Third, behavioural parity with the PowerShell broker it replaces, covering the control grammar, child environment, command resolution, deadline accounting and complete-tree stop, has not been established. Private copied-root fixtures have exercised launch, job membership and verified stop through this binary, as recorded in [selected-image fixture evidence](../../../.nightshift/reports/runtime-selected-image-fixture-evidence-20261019.md), but that is exercise, not a parity proof.
