# .NET first-run side effect during startup probe

On 2026-10-14, a private startup-latency probe built a minimal .NET app under repository `.tmp` with `DOTNET_CLI_HOME`, `NUGET_PACKAGES`, `NUGET_HTTP_CACHE_PATH`, `TEMP` and `TMP` redirected into the repository. The first `dotnet build --no-incremental` succeeded, but its output said it installed an ASP.NET Core HTTPS development certificate. The Windows certificate store was not inspected, so the output is evidence of a likely host-level change rather than independent confirmation of one. The hard project limit forbids writes outside the repository, and redirecting cache and temp paths did not account for this first-run behavior. No further SDK command was run in that probe; the already-built private apphost was benchmarked with repository-local temp paths and .NET diagnostics disabled.
